# Scene wishes for V145: What actions/checkout does by default

Spots are given as section heading plus the first six words of the paragraph in `video/scripts/V145-*.md`. Every label is copied from the script. One library scene is already placed (the full clone as a `graph`, LIVE TERMINAL DEMO, "Here's that clone as a picture:").

## 1. The cut in history (shallow clone)

- **Spot.** LIVE TERMINAL DEMO, Step 2, "One line of log, with the". Bring it back at CONCEPT, "**Inside `.git`.** Every commit names its".
- **Picture.** The row of three commits from the scene already placed, then the same row as the runner has it.
- **Steps.**
  1. `full`: `05d3477`, `ae299cb`, `6fe5455` in a row; tag `v0.1.0` on `ae299cb`; `main` and `HEAD` on `6fe5455`. Caption: "Your clone: three commits, one annotated tag."
  2. `cut`: a vertical cut line appears left of `6fe5455`. `05d3477` and `ae299cb` change to a style that means "not in this clone" (not the ghost style, which means unreachable). The tag `v0.1.0` disappears. The word `grafted` appears on `6fe5455`.
  3. `file`: a file card `.git/shallow` appears holding `6fe5455926c26261fe2c73104018ca2d96fdb554`, with a line from the card to the cut.
  4. `counts`: three small read-outs: `git rev-parse --is-shallow-repository` `true`; `git tag --list` (empty); `git rev-list --count HEAD` `1`.
- **Why not today.** `graph` refuses fewer than two commits and has no "absent from this clone" style, no cut line and no file card.

## 2. A walk that stops at the cut

- **Spot.** CONCEPT, "Think about what "no parents" does."
- **Picture.** The cut row of wish 1 with a walker that starts at `HEAD` and moves left along the parent edges.
- **Steps.**
  1. `describe`: the walker is labelled `git describe`, looking for "a tagged commit"; it reaches the cut and stops.
  2. `log`: the walker is labelled `git log`, looking for "the commit that changed the file"; it stops at the cut.
  3. `merge-base`: the walker is labelled `git merge-base`, looking for "a common ancestor"; it stops at the cut.
  4. `all`: caption "None of them can see past the cut."
- **Why not today.** No scene has a moving walker or a cut.

## 3. Fail or lie

- **Spot.** LIVE TERMINAL DEMO, Step 3, "`git describe --tags` fails: "No names" through "And `git merge-base` fails, because the".
- **Picture.** Three cards side by side, each a command with its answer and a verdict stamp.
- **Steps.**
  1. `fails`: `git describe --tags` gives `fatal: No names found, cannot describe anything.` and `exit status: 128`; stamp FAILS with a red cross; small "red job".
  2. `lies`: `git describe --tags --always` gives `6fe5455` and `exit status: 0`; stamp LIES in amber; small "green job"; caption "One flag turned a failure into a lie."
  3. `worst`: `git log --oneline -- java-service/pom.xml` gives `6fe5455 Document how to run the tests`; stamp LIES; under it, the true answer `ae299cb Add Maven module for price calculation` arrives later (Step 5).
- **Why not today.** No verdict cards; a terminal slide cannot stamp a line.

## 4. The tag arrives, the walk still stops

- **Spot.** LIVE TERMINAL DEMO, Step 4, "B. The tag arrived, and `describe`", then Step 5, "Not shallow, three commits, the right".
- **Picture.** The cut row of wish 1.
- **Steps.**
  1. `tag-arrives`: `v0.1.0` appears on `ae299cb`, which is still on the far side of the cut. Caption: `fetch-tags: true` with depth 1.
  2. `walk`: the walker from `HEAD` stops at the cut before the tagged commit; message `fatal: No tags can describe '6fe5455926c26261fe2c73104018ca2d96fdb554'.`
  3. `unshallow`: command line `git fetch --unshallow --tags`; the cut line and the `.git/shallow` card disappear; all three commits are solid.
  4. `describe`: the walker reaches `ae299cb`; read-out `v0.1.0-1-g6fe5455`. Caption: `fetch-depth: 0`.
- **Why not today.** Same limits as wish 1.

## 5. The merge ref: three commits, two HEADs

- **Spot.** DIAGRAM, "Try it now, on paper. Thirty" (it replaces the ASCII drawing), and again at LIVE TERMINAL DEMO, "The tests fail on the runner".
- **Picture.** The drawing of section 20A.8 built in the order the stage direction gives.
- **Steps.**

  2. `branch`: `80c9cfa` from `6fe5455`, labels `feature/reorder-report` and `refs/pull/7/head`, marker "your HEAD".
  3. `question`: a question mark where the merge will be; caption "Where is CI's commit?"
  4. `merge`: `d04ef31` with parents `29b222b` and `80c9cfa`, label `refs/pull/7/merge`, marker "runner HEAD (detached)"; a boundary or tint that says "exists only on the server".

## 6. From the event to the checkout

- **Spot.** CONCEPT, "**The merge ref.** Chapter 17 showed that".
- **Picture.** A short left-to-right flow.
- **Steps.**
  1. `event`: chip `pull_request`.
  2. `variables`: two read-outs: `GITHUB_REF` = `refs/pull/N/merge`, `GITHUB_SHA` = "that commit".
  3. `checkout`: box `actions/checkout`, quotation "checks out the merge branch".
  4. `head`: result box "detached HEAD", quotation "CI tests run against the merged result, not just the head branch alone".
- **Why not today.** `ci` always draws a workflow file, a job and a runner name that this script does not give, and has no variable read-outs.

## 7. When the test merge is rebuilt, and when it is not

- **Spot.** CONCEPT, "First, the test merge can be", then "Second, a conflicted pull request has".
- **Picture.** A timeline for one pull request.
- **Steps.**
  1. `regenerated`: three markers on the line, each rebuilding the test merge: "the pull request branch is pushed", "the merge base changes", "older than 12 hours".
  2. `re-run`: a re-run arrow that points back at the old commit; caption "A re-run reuses the original commit."
  3. `conflict`: the merge ref greys out; caption "A conflicted pull request has no merge ref"; where the checks would be: "missing checks, not failed ones".
- **Why not today.** No timeline scene.

- **Spot.** LIVE TERMINAL DEMO, ""Could not get object info." The commit".
- **Picture.** Two boxes: "your clone" and "runner".
- **Steps.**
  1. `missing`: in "your clone", `git cat-file -t` of `d04ef31` answers `fatal: git cat-file: could not get object info`.
