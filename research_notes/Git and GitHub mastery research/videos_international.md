# International (non-Indian) Git and GitHub video resources: evaluated catalogue as of 1 October 2026

**Verification method (applies to every entry below).** Every video listed was verified on 1 October 2026 against YouTube itself: for almost all entries by retrieving the watch page (exact title, channel, duration and upload date come from YouTube's own metadata), and for a handful of secondary items (some series episodes and playlist members, shown without an upload date) from YouTube's own search, channel or playlist listings. Nothing is listed that YouTube did not return. Fields I could not confirm are marked "unverified". Basis-of-assessment tags used on every entry:

- **[T-manual]** = full transcript retrieved from the video's human-supplied caption track; **[T-asr]** = transcript retrieved from YouTube's auto-generated captions (speech-recognition errors possible). In both cases I analysed the transcript by keyword frequency and by reading targeted excerpts with timestamps (written "t=mm:ss"); I did not watch the video or read every transcript end to end. 197 transcripts were retrieved this way.
- **[C]** = assessed from the chapter list and description only. **[D]** = assessed from title and description only. For [C] and [D] entries, technical correctness and depth were not assessed; they are listed as verified-to-exist pointers with whatever the metadata supports.
- Levels: B = beginner, I = intermediate, A = advanced, E = expert/contributor-level.
- "Current?" judgments are made against the October 2026 baseline documented under the key question on outdated content (Git 2.56.0 is the latest release; Git 3.0 is not yet released; actions/checkout is at v7).

## Git internals and mental-model talks (Scott Chacon, classic internals talks, Git Merge 2022-2026, Git contributors)

### Takeaway
Every talk named in the brief exists and is still viewable; the object-model talks from 2007-2018 remain technically sound on blobs, trees, commits and refs but uniformly assume `master`, `git checkout` and SHA-1. The freshest expert material is the Git Merge series on the GitButler channel, including the Git Merge 2026 (Lisbon, 17-18 September 2026) talks that were uploaded on the evaluation date itself.

### Inferences
- For a curriculum, the object-model talks are interchangeable on correctness; the choice is about format and length: Britton (structured, 58 min), Thomas (hands-on, 31 min), Berglund (plumbing lab, 56 min), Cook (graph reasoning, 49 min), Schwern (physical model, 100 min). All need a one-line caveat about `master`, `checkout` and SHA-1.
- None of the classic talks covers packfiles, pack indexes, commit-graph or bitmaps in any depth; Stolee's 2022 talk is the only compact, accessible video that does, and Blau's talks are the contributor-level continuation.
- The Git Merge 2025 and 2026 talks are the only verified videos by core contributors that discuss Git 3.0, SHA-256 interoperability, reftable-by-default and Rust; they are expert-level and assume internals knowledge.
- Chacon's two "So You Think You Know Git" talks are tips surveys, not internals talks; they belong after the learner already has the model.

## GitHub, GitHub Actions, and security (TechWorld with Nana, freeCodeCamp, GitHub's channel, Universe 2024-2025, Actions attack talks, tj-actions, Mickey Gousset, DevOps Journey, glich.stream, 2025-2026 courses)

### Takeaway
For Actions basics the best free course is DevOps Directive's "Complete GitHub Actions Course - From BEGINNER to PRO" (3:42:35, September 2025), which teaches `GITHUB_OUTPUT`, least-privilege `permissions`, OIDC and SHA pinning; the widely linked TechWorld with Nana tutorial (October 2020) is now only a conceptual primer. Actions security is unusually well served by conference talks from 2023-2026, but GitHub's own Universe 2024 and 2025 uploads contain almost nothing dedicated to Actions security or rulesets, and Universe 2026 has not happened yet.

### Inferences
- The teaching order that the evidence supports is: DevOps Directive course for mechanics, then Adnan Khan's RomHack talk for how workflows are attacked, then Niek Palm's NDC Security 2026 talk for hardening, then the BSides PDX tj-actions talk as the incident case study, with Woodruff's zizmor talk as the tooling insert.
- GitHub's official channel is adequate for feature awareness (rulesets, merge queue, secret protection, Copilot review, stacked PRs) but the videos are 1-10 minutes and marketing-adjacent; none is a substitute for the documentation on configuration detail.
- Any Actions tutorial older than about 2023 should be assumed to show superseded action versions and to omit `permissions`, pinning and OIDC; this applies to TechWorld with Nana (2020), DevOps Journey (2021), glich.stream E1 (2021), Edward Thomson's NDC talk (2020) and Mickey Gousset's NDC talk (2021).

### Inferences
- Engineering-judgment talks need the least currency caveating of any category; the exceptions are scale talks whose technology has moved on (GVFS, 2015 Google numbers).
- The trunk-based material is advocacy; a curriculum should pair one advocate (Farley or Farcic) with the neutral 2026 TechWorld with Nana overview and Tobias Günther's branching-strategies chapter so learners see the trade-off rather than a verdict.
- "A Branch in Time" is unusually good for a mastery curriculum because it motivates `git log -S`, `git blame`, interactive rebase and `--force-with-lease` through a single narrative.

### Gaps
- I found no conference talk that covers production incident recovery end to end with current tooling (leaked secret rotation, `git filter-repo`, coordinated force-push, recovering a force-pushed branch on GitHub); the 2017 Git Merge talk is the nearest and uses superseded tools.
- No verified English talk compares GitHub merge queue, rulesets and trunk-based development together.
- The two code.talks recordings were only sampled at the start; their depth is unassessed.

### Inferences
- Official documentation or books are required for: ruleset and merge-queue configuration, CODEOWNERS and required-check design, secret scanning and push-protection response, artifact attestations and immutable releases, OIDC claim configuration, the pack format and wire protocol, `rerere`/`range-diff` and the newer history commands, Git 3.0 migration (SHA-256 interoperability, reftable), and a full incident runbook (rotate secret, rewrite history with git-filter-repo, coordinate force-push, recover overwritten refs).
- A curriculum should treat GitHub's short official clips as "what exists" pointers and send learners to the documentation for the actual configuration steps, because the UI and policy options changed in 2023, 2025 and 2026.
- The talks by Git contributors at Git Merge 2024-2026 are the right capstone for an expert tier, but none is suitable before the learner has completed the object-model and storage-internals stages.
- If only one video per tier can be assigned: beginner tier Missing Semester 2026; intermediate tier Boot.dev full course; advanced tier Chacon FOSDEM 2024; platform tier DevOps Directive; security tier Niek Palm NDC Security 2026.

### Gaps
- I did not find a video that teaches GitHub code review end to end (review requests, CODEOWNERS, suggested changes, merge methods, rulesets, merge queue) with the 2026 interface.
- I did not search for or evaluate videos on Git LFS administration, Git hooks security, or GitHub Enterprise administration beyond what surfaced incidentally.
- "Best single choice" selections rest on transcript sampling, chapter lists and descriptions, not on watching each video in full; a human spot-check of the core picks is advisable before publishing a curriculum.
- Documentation URLs for the areas listed as "docs required" were not collected here; that is covered by the researchers working on official documentation.
