# Work packages — textbook, demos and labs (wave 1)

Each work package (WP) is owned by one author. Write only the files listed for your WP. Other authors are writing the other chapters at the same time, so refer to their material by chapter number and title, never by copying it.

## Common inputs for every WP

1. `authoring/STYLE_GUIDE.md` — binding rules. Read it first, completely.
2. `labs/lib/lab-env.sh`, `labs/ch00/smoke-test.sh`, `labs/ch00/out/smoke-test/*.txt` — how demos work.
3. `curriculum/Git and GitHub mastery roadmap.md` — find your modules with `grep -n "#### Module"`; the module entries list topics, labs and primary sources you must cover.
4. `reports/Git and GitHub mastery research.md` — the verified facts (Phase 0 report). Read the sections named in your brief. Line ranges: §1 lines 9-125, §2 126-274, §3 275-370, §4 371-448, §5 449-502, §6 503-557, §7 558-657, §8 658-681, §9 682-704, §10 705-773, §11 774-823, §12 824-903, §13 904-1006, §14 1007-1126, §15 1127-1195. The file has very long lines: read it in ranges of at most about 60 lines at a time.
5. `research_notes/Git and GitHub mastery research/*.md` — deeper notes with source links: `git_core_landscape.md`, `github_platform.md`, `github_actions.md`, `books_docs_misconceptions.md`, `aiml_workflows_and_security.md`, `videos_indian_educators.md`, `videos_international.md`. They are large: search them with `grep -n` for your topics instead of reading them whole.
6. The local manual: `git help -m <command> | col -b` is the authoritative documentation of the Git 2.55.0 the learner runs.

## Common outputs for every WP

- The textbook chapter file or files named in the brief, following the chapter structure in the style guide.
- Demo scripts under `labs/<dir>/` with generated snippets under `labs/<dir>/out/`.
- The lab-manual files named in the brief, in the eleven-part lab format, each lab with a replay script.
- `solutions/mNN-lab-answers.md` with answers to each lab's "Questions".
- All four checks green: `tools/build-demos.sh <dir>`, `python3 tools/inject.py <your md files>`, `labs/verify-all.sh <dir>`, `python3 tools/check_course.py <your md files>`.

Length targets are for the chapter text including transcripts. They are targets for completeness, not quotas: never pad, and never drop a listed topic to stay short.

The numbered references "§N" in the briefs below are sections of the learner's original brief; you do not need that document. Everything required is spelled out here and in the roadmap.

A replay script captures the solution as real transcripts by sourcing the generator inside its own sandbox:

```bash
# labs/incidents/solve-01-hard-reset.sh
. "$(dirname "$0")/../lib/lab-env.sh"
lab_begin incidents solve-01-hard-reset
LAB_REPLAY=1 . "$COURSE_ROOT/incidents/01-hard-reset/generate.sh"

lab_end
```

Because both paths start from the same clock and run the same commands, the commit IDs are the same in the learner's sandbox and in the printed solution. A `check.sh` beside the generator verifies the learner's recovery with read-only commands and exits 0 on success.
