## 4. CONCEPT, "The REST API is a set" through "Not found means "not for you"."

**Picture.** One request card that is assembled part by part, one part per "rule of the road".

1. Path: `repos/{owner}/{repo}/pulls`; the placeholders `{owner}` and `{repo}` fill themselves "from the current repository".
2. Method chip: `GET` by default; adding `-f` or `-F` flips it to `POST`; `-X GET` pins it.
3. Fields: `-f` "a string"; `-F` "`true`, `false`, `null` and integers to JSON types".
4. Pages: "30 items per page"; `--paginate`; `--slurp`.
5. Header: `X-GitHub-Api-Version`; without it `2022-11-28` ("supported until the tenth of March 2028"); `2026-03-10` "the first version with breaking changes"; an unsupported version answers `410 Gone`; the CLI pins `2022-11-28` "since version 2.87.0".
6. Response chip for a private resource without access: `404`, with the documentation's words "to avoid confirming the existence of private repositories".

Caveat line under the picture, from the script: "The paths and field names were checked against the REST reference on the second of October 2026. The commands weren't run."

## 6. CONCEPT, "**Webhooks and GitHub Apps.** Polling asks" and "A GitHub App is the identity"

**Picture.** Two directions of traffic between your server and GitHub.

1. `poll`: your server asks GitHub again and again ("whether something happened"), most answers empty.
2. `webhook`: the arrow reverses; "you register a URL and the events you care about"; on a `push`, GitHub sends "an HTTP request with a JSON payload" that carries "the ref and the commit IDs before and after the push"; a small reflog line appears beside the payload ("the information of a reflog line, delivered to your server").
3. `app`: an App card with five properties arriving one by one: "installed on chosen repositories", "fine-grained permissions", "receives webhooks", "installation tokens that expire after one hour", "isn't tied to a person".
4. `alternatives`: two dimmed cards, "a personal token, which acts as you everywhere you have access" and "a machine user".

An amber "Unverified" tag stays for the callout: webhook delivery retries and signature validation are not described in the course.
