## 5. The two halves of a filter, and what a clone gets

- **Spot.** LIVE TERMINAL DEMO, "The attribute travelled, because `.gitattributes` is" (after snippet `07-clone`), and MENTAL MODEL, "For the filter: a mail room".
- **Picture.** Your clone and Asha's clone (`docqa-asha`), with `server.git` between them.
- **Steps.**
  1. In your clone, two parts: the tracked file `.gitattributes` ("filter: nbstrip") and the configuration `.git/config` (`filter.nbstrip.clean`, `filter.nbstrip.required`).
  2. `git clone`: `.gitattributes` travels through the server to Asha's clone. `.git/config` stays behind.
  3. In Asha's clone: `git check-attr filter` answers `nbstrip`; `git config get filter.nbstrip.clean` answers `[exit status: 1]`.
  4. Asha commits and pushes: the notebook arrives on the server "with outputs", `3`. No error, no warning.
