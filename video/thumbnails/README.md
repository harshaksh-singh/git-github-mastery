# Thumbnails for the video course

One 1280x720 PNG per video, V001 to V201, in the house style of the course: a dark background, one accent color per course part, a two-line headline, a kicker line, a terminal chip with one command the video teaches, a diagram on the right, and the video number in the top right corner.

## Files

| File | What it is |
|---|---|
| `thumbnail-data.json` | The source of truth: one object per video with `id`, `part`, `headline`, `kicker`, `command`, `motif`, `youtube_title` and `description`. |
| `V001.png` to `V201.png` | The rendered thumbnails, 1280x720, ready to upload. |
| `html/V001.html` to `html/V201.html` | The intermediate page for each thumbnail (one inline SVG). Open one in a browser to inspect or debug a layout. |
| [`../youtube-metadata.md`](../youtube-metadata.md) | Title, description and thumbnail file for each video, grouped by part, for uploading. |
| [`../../tools/build_thumbnails.py`](../../tools/build_thumbnails.py) | The generator. |

## The art is generated by code

No image model and no hand drawing is involved. `tools/build_thumbnails.py` writes an SVG for each entry and headless Chrome takes a screenshot of it. Every label and every command on a thumbnail is therefore exact text taken from `thumbnail-data.json`: nothing is approximated, misspelled or invented by a renderer. Each `command` is copied from that video's entry in [`../video-curriculum.md`](../video-curriculum.md), so the command on the thumbnail is one the video teaches. The diagrams are deterministic: the same entry always gives the same picture.

## How to regenerate

1. Edit `thumbnail-data.json`.
2. From the course root, render everything or only the entries you changed:

```
python3 tools/build_thumbnails.py              # all 201, a few minutes
python3 tools/build_thumbnails.py V001 V045    # only these
```

The generator needs Google Chrome at its default macOS location. If Pillow is installed, the headline and the kicker are fitted with the real widths of the system font; without it a conservative estimate per character is used, and the text comes out slightly smaller.

## Rules for the data

| Field | Rule |
|---|---|
| `headline` | 2 to 4 words, at most 22 characters, unique. It is drawn in capitals on two lines, balanced automatically; a `\n` in the text forces the line break. |
| `kicker` | One line, at most 34 characters, unique. It completes the headline and makes no promise the video does not keep. |
| `command` | At most 30 characters, a command or setting from the video's entry in the curriculum, or empty for briefings and design talks. |
| `motif` | One of: `compass`, `graph`, `incident`, `key`, `merge`, `objects`, `pack`, `pipeline`, `rebase`, `recover`, `remote`, `review`, `search`, `shield`, `trees`. |
| `youtube_title` | At most 70 characters, unique. The series suffix is added only where it fits. |
| `description` | Two sentences, at most 300 characters. |

The text column ends at x = 692 and the diagram starts at x = 724. A long word makes the whole headline smaller, so prefer short words: lines of up to nine characters render at the largest size.
