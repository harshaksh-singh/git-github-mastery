# Scene wishes for V153: "Passes locally, fails on GitHub Actions": the documented causes

Spots are given as section heading plus the first six words of the paragraph in `video/scripts/V153-*.md`. Every label is copied from the script. What the Actions pages do not state (time zone and locale of hosted runners, CRLF on Windows runners, case sensitivity of the hosted runners' filesystems) is marked Unverified in the script: the runner column of any picture says "the general rule for Linux", never "observed". One library scene is already placed (`graph` of the six-commit history with its two tags, LIVE TERMINAL DEMO, Case 3, "Here's that history as a picture:").

## 1. The same commit, and four other inputs

- **Spot.** MENTAL MODEL, ""Same commit" means: the same tree,", through "So when someone says "it is".
- **Picture.** A commit card in the middle ("the same tree, the same bytes in every blob, the same names") and four cards that arrive around it.
- **Steps.**
  1. `filesystem`: "The filesystem that the names are written onto."
  2. `depth`: "How much of the repository came along."
  3. `which-commit`: "Which commit the job took."
  4. `shell`: "the process that runs your command: the shell and its options".
  5. `ask`: the speech line "it is the same commit" with a tick, then four question marks on the four cards.
- **Why not today.** No scene for one object with surrounding inputs.

## 2. Your Mac and the runner, row by row

- **Spot.** DIAGRAM, "Try it now. Thirty seconds, in" (it replaces the ASCII table).
- **Picture.** Two columns, "your Mac" and "the runner (Linux job)", filled one row at a time, left cell first.
- **Steps.** One per row, with the labels of the DIAGRAM table: "filesystem" ("ignores case by default; core.ignorecase = true" / "case-sensitive (the general rule for Linux; not stated on the Actions pages)"), "checkout depth" ("full history" / "one commit; .git/shallow lists it"), "tags" ("all tags" / "none"), "commit tested" ("your branch tip" / "on pull_request: the test merge under refs/pull/N/merge, detached HEAD"), "shell for run:" ("your interactive shell" / `bash -e {0}` without a shell key; `bash --noprofile --norc -eo pipefail {0}` with `shell: bash`). - **Why not today.** A table slide cannot fill the left cell before the right one.

## 3. One recorded name, two filesystems

- **Spot.** CONCEPT, "**Why the two Git causes happen"; LIVE TERMINAL DEMO, Case 1, "Look at the three results together.", "B. 128 for the lower-case name,", "The status shows a rename, `R`,".
- **Picture.** In the middle, Git's record: the name `configs/Thresholds.yaml`. Left, a Mac disk; right, a Linux disk. The code asks for `configs/thresholds.yaml`.
- **Steps.**
  1. `recorded`: the index entry `configs/Thresholds.yaml`, capital T highlighted; `core.ignorecase` = `true`.
  2. `mac`: the request `configs/thresholds.yaml` reaches the Mac disk and the file opens: "the filesystem answers for both spellings".
  3. `linux`: the same request reaches the Linux disk: file not found.
  4. `proof`: `git cat-file -e HEAD:configs/thresholds.yaml` gives `exit status: 128` and "exists on disk, but not in 'HEAD'"; `git cat-file -e HEAD:configs/Thresholds.yaml` gives `exit status: 0`.
  5. `fix`: `git mv configs/Thresholds.yaml configs/thresholds.yaml`; the recorded name changes; status line `R  configs/Thresholds.yaml -> configs/thresholds.yaml`; both disks now open the file.
- **Why not today.** `trees` shows one file in three places but cannot show a name differing between the index and a request, or two filesystems.

## 6. Three columns for one file: index, working tree, attributes

- **Spot.** LIVE TERMINAL DEMO, Case 2, "`i/crlf`. The committed blob itself contains", "`i/lf`, the attribute `text eol=lf`, and", "Now all three columns agree, and".
- **Picture.** Three boxes for `scripts/deploy.sh`, labelled `i/` ("the index, which is what is committed"), `w/` ("the working tree") and `attr/` ("the attributes in force").
- **Steps.**
  1. `before`: `i/crlf`, `w/crlf`, `attr/` empty; `core.autocrlf` unset; caption "Every clone of this commit gets those bytes."
  2. `attributes`: `.gitattributes` with `* text=auto` and `*.sh text eol=lf`; the `attr/` box shows `text eol=lf`.
  3. `renormalize`: `git add --renormalize .` and the commit; `i/` becomes `i/lf`; `w/` is still `w/crlf`; caption "The index is fixed. This working tree still has the old bytes".
  4. `fresh-clone`: a second, small working tree labelled "a fresh clone, which is what a runner makes": `w/lf`.
  5. `restore`: `git restore scripts/deploy.sh` (red, with a warning triangle): `w/lf`; all three agree; `would deploy to staging`.
- **Why not today.** `trees` has no attributes box, its boxes hold versions, not line-ending states, and its `add` step copies the working tree into the index, which is the opposite of what `--renormalize` shows here.

## 7. One commit of six, then tags without a path, then the whole history

- **Spot.** LIVE TERMINAL DEMO, Case 3, "One commit, marked "grafted". No tags.", "Fetching the tags alone, still at", "Not shallow, six commits, and the".
- **Picture.** The six-commit row of the scene already placed: `91fe9ab`, `e797c71` (`v1.0.0`), `3c8340d`, `c4b5de2` (`v1.1.0`), `197d992`, `57c8425` (`main`).
- **Steps.**
  1. `shallow`: only `57c8425` stays solid, marked "grafted"; the five older commits take an "absent from this clone" style; both tags disappear; read-outs `true` and `fatal: No names found, cannot describe anything.`
  2. `tags-only`: `v1.0.0` and `v1.1.0` reappear on their commits, which are still absent; the walk from `HEAD` stops at the cut; read-out `fatal: No tags can describe '57c8425908f43c74c14b2642edb59e0f99dac38c'.`
  3. `unshallow`: `git fetch --quiet --unshallow --tags`; all six commits solid; the walk reaches `c4b5de2`; read-out `v1.1.0-2-g57c8425`.
- **Why not today.** `graph` refuses a one-commit state and has no "absent from this clone" style (ghost means unreachable).
