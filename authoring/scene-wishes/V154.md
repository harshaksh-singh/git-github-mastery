# Scene wishes for V154: Required checks that stay pending, the debugging instruments, linting, and what a local emulator cannot reproduce

Spots are given as section heading plus the first six words of the paragraph in `video/scripts/V154-*.md`. Every label is copied from the script. The six reports of Lab 28.1 are "constructed descriptions written from the documented behavior", not captured logs, and the robust design is labelled "an inference from these rules": no picture may look like a captured merge box or run. No library scene was placed in this pass: `pr: ... blocked` always draws a review row, a number and commit letters that this script does not give, `hash` needs the content of `uv.lock`, which the transcript does not print, and the demo prints no commit IDs for the branch tips.

## 1. A check that nobody will report

- **Spot.** HOOK, "A pull request is GitHub's proposal", through "Both attempts were reasonable and both".
- **Picture.** A plain pull request card with one row: a required check with an amber dashed ring and the words "Waiting for status to be reported". Where the run would be: an empty outline, "No run exists."
- **Steps.**
  1. `stuck`: the card; nothing red, nothing to click.
  2. `re-run`: a "re-run" arrow looks for a run and finds the empty outline; caption "There is nothing to re-run."
  3. `by-hand`: a run started by hand appears beside the card and goes green; the ring on the card does not change; caption "a run started by hand is not evaluated for the pull request".
  4. `why`: a filtered-out workflow behind a filter; caption "never reports the name the rule is waiting for".
- **Why not today.** `pr` cannot hide its review row, number and commit letters, and has no state "no run exists".

## 5. The aggregate job under four conditions

- **Spot.** CONCEPT, "Read it against the table. The".
- **Picture.** Three job boxes: `unit-tests`, `lint`, and `all-checks` with `needs: [unit-tests, lint]` and `if: ${{ !cancelled() }}`.
- **Steps.**
  1. `all-pass`: both needed jobs green; `all-checks` runs, its one step is skipped, green.
  2. `one-fails`: `unit-tests` red; `all-checks` still runs ("not skipped when a needed job fails") and its step `exit 1` makes it red.
